# Release Readiness Lite Design

## Goal

Make Citadel's local Windows alpha packaging path trustworthy enough to produce and manually smoke-test an installer and portable build.

This is a local release-readiness pass. It should verify and document the package path before adding release automation, signing, or auto-update publishing.

## Scope

In scope:

- Confirm `npm run package` is the canonical local alpha packaging command.
- Verify Electron Builder configuration for Windows NSIS and portable targets.
- Check required packaging assets, especially `resources/icon.ico`.
- Add or repair missing local packaging prerequisites that belong in the repo.
- Document expected `dist/` outputs.
- Add a manual smoke-test checklist for packaged artifacts.
- Add release-readiness documentation with known limitations and next steps.

Out of scope:

- GitHub Actions release workflow.
- Code signing certificates.
- Auto-update publishing.
- Version bump automation.
- Installer customization beyond making the current config package cleanly.
- Full end-to-end Playwright coverage for packaged binaries.

## Release Artifact Target

The local alpha target is a Windows package produced by:

```bash
npm run package
```

The expected outputs are:

- An NSIS installer for x64 Windows.
- A portable `.exe` for x64 Windows.
- Build metadata and unpacked app output under `dist/` as generated by Electron Builder.

The existing package identity should remain:

- Product name: `Citadel`
- App id: `com.citadel.app`
- Project file associations: `.citadel` and `.citadelz`

If packaging fails because a required repo asset is missing, such as `resources/icon.ico`, the implementation should fix the repo-owned prerequisite or make the configuration explicit. It should not leave packaging dependent on an untracked local file.

## Packaging Checks

The implementation should inspect and, if needed, adjust:

- `package.json` build config.
- `electron.vite.config.ts`.
- `resources/` packaging assets.
- `.gitignore` treatment of generated release outputs.
- README or docs references to release commands.

The app should continue to use `dist/` for packaged artifacts and `out/` for Electron Vite build output. Generated artifacts should remain ignored by git.

## Manual Smoke Checklist

Add a concise checklist for validating a local alpha package. The checklist should cover:

- `npm.cmd run build` succeeds.
- `npm run typecheck` succeeds.
- `npm test -- --run` succeeds.
- `npm run package` succeeds or has a documented environmental blocker.
- Installer and portable artifacts exist in `dist/`.
- Portable app launches.
- Installed app launches, if the installer is run.
- New project opens to a usable canvas.
- Drag/drop import works for at least one image.
- Save and load `.citadel` works.
- Export image or PDF succeeds.
- `.citadelz` export and import are sanity checked when practical.
- Unsaved guard appears before replacing dirty work.
- Recovery prompt appears after a simulated unsaved session when practical.
- Recent projects list and key panels open.

The checklist should be written for a human tester and should distinguish required checks from optional checks that depend on time or environment.

## Documentation

Create a release-readiness document under `docs/` that includes:

- Prerequisites.
- Build/package commands.
- Expected outputs.
- Manual smoke-test checklist.
- Known limitations for the alpha package.
- Troubleshooting notes for common packaging failures.
- Next release-readiness steps.

The document should link to `docs/citadel-capabilities-guide.md` for feature coverage instead of repeating the full capabilities guide.

Known limitations should be explicit. At minimum, this alpha pass should note:

- Builds are unsigned unless signing is added later.
- GitHub release automation is not part of this slice.
- Auto-update publishing is not part of this slice.
- Manual smoke testing is required before sharing an artifact.

## Error Handling and Reporting

If `npm run package` fails, the implementation should capture the important failure cause in the final report and in the release-readiness doc if the issue is environmental or expected. If the failure is caused by repo configuration, the implementation should fix it within this slice.

The final report should state:

- Whether packaging was attempted.
- Whether packaging succeeded.
- Which artifacts were produced, if any.
- Which verification commands passed.
- Any remaining release blockers.

## Testing

Verification should include:

```bash
npm.cmd run build
npm run typecheck
npm test -- --run
npm run package
git diff --check
```

If packaging cannot complete because of an environmental condition, all other verification should still run, and the packaging blocker should be documented with enough detail to reproduce it.

## Acceptance Criteria

- A release-readiness doc exists under `docs/`.
- Packaging expectations and smoke-test steps are documented.
- Repo-owned packaging prerequisites are present or explicitly handled.
- `npm.cmd run build`, `npm run typecheck`, and `npm test -- --run` pass.
- `npm run package` either succeeds or fails only for a clearly documented environmental blocker.
- Generated release artifacts remain out of git.
- No release automation, signing, or updater publishing is added in this slice.
